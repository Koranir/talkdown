# Harper checking and Codex model settings — 2026-07-21

This note records the API decisions behind Talkdown's local dictation checker
and Codex model selector. Reverify both dependencies before changing their wire
or lint behavior.

## Harper boundary

Talkdown uses `harper-core` 2.5 with default features disabled. Harper describes
its core as the Rust tokenization, parsing, analysis, and linting engine, and its
project explicitly targets private, millisecond-scale local checking:

- <https://writewithharper.com/docs/contributors/architecture>
- <https://github.com/Automattic/harper/tree/v2.5.0/harper-core>

The application keeps one curated American-English `LintGroup` and parses each
final literal transcript with `PlainEnglish`. Automatic application is narrower
than Harper's complete curated output: Talkdown accepts only non-overlapping
lints with exactly one suggestion in the agreement, boundary, capitalization,
grammar, miscellaneous, punctuation, repetition, or typo categories. It skips
spelling, style, enhancement, readability, regional preference, and every lint
with multiple alternatives. This is a product safety policy, not a Harper API
requirement.

Harper operates on character spans, so fixes are applied to a standalone
transcript before Talkdown re-adds cursor-sensitive word-boundary spacing. The
final trusted replacement amends the immediately preceding optimistic insertion
and therefore remains one undo transaction. Contextual commands never go
through Harper.

Talkdown retains the latest Harper pass as an in-memory decision audit. Applied
and ignored records include the lint kind, original character span, message,
and rendered suggestions. Ignored records additionally identify policy-excluded
categories, missing suggestions, ambiguous alternatives, or overlap with the
selected non-overlapping lint set. If the final trusted document amendment
fails, its selected findings move to ignored with a validation reason. The
Checker tooltip presents a bounded view of this audit. It is intentionally neither persisted nor externally logged,
because Harper messages can contain dictated text.

## Codex model discovery

The implementation was checked against `codex-cli 0.144.5` and the JSON schemas
generated by that exact binary:

```sh
schema_dir=$(mktemp -d /tmp/talkdown-codex-schema.XXXXXX)
codex app-server generate-json-schema --out "$schema_dir"
```

The official app-server guide says clients should call `model/list` before
rendering model selectors, and shows `model` as a `thread/start` parameter:

- <https://developers.openai.com/codex/app-server/#models>
- <https://developers.openai.com/codex/app-server/#start-or-resume-a-thread>

Talkdown paginates `model/list` with `includeHidden: false`, retains `model`,
`displayName`, `description`, and `isDefault`, and sends the selected `model`
string only when the user does not choose “Codex CLI default.” It does not
hardcode a model catalog. A persisted model that disappears from the advertised
list remains visible as unavailable, and Settings blocks Apply until the user
selects an advertised model or the CLI default.

Changing the model replaces the idle Codex bridge and starts a new ephemeral,
read-only, approval-free thread. Settings cannot open while an edit is pending,
which avoids dropping an in-flight response during that replacement. The
ChatGPT-account and OpenAI-provider checks remain unchanged.
